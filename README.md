# Money Grid — мобильный трекер личных расходов

Учёт финансов без текстового ввода: три блока иконок на главном экране, деньги
перетаскиваются между ними пальцем.

```
Доходы  ──drag──▶  Кошельки  ──drag──▶  Расходы
(Работа,           (Наличные,           (Еда,
 Подработка…)       Карты, Долги)        Транспорт…)
```

## Как это работает

| Жест | Что происходит |
|---|---|
| Тап по «+» в любом блоке | редактор нового кружка: название, цвет, иконка (у кошелька ещё тип и валюта, у расхода — лимит) |
| Тап по иконке дохода | окно ввода суммы — доход зачисляется в категорию, но ещё не лежит в кошельке |
| Потянуть иконку дохода на кошелёк | окно с суммой (по умолчанию весь нераспределённый остаток) — доход разносится по кошелькам, один доход можно разбить на несколько |
| Тап по категории расхода | окно «сумма + откуда списать» |
| Потянуть кошелёк на категорию расхода | то же окно, кошелёк уже выбран |
| Потянуть кошелёк на кошелёк | перенос денег; если цель — долг «я должен», это погашение |
| Тап по кошельку | баланс и ручная корректировка |
| Тап по «Долги −» / «Долги +» | список долгов этого вида |
| Долгое нажатие на категорию расхода | настройки категории |

Долгое нажатие на доходах и кошельках занято перетаскиванием, поэтому их
настройки открываются из окна ввода (доходы) и из карточки кошелька.

## Что внутри

- регистрация по почте и паролю: у каждого своя учётная запись и свои данные
- пустой старт: ни категорий, ни кошельков — всё заводится через «+»
- мультивалютность: тенге, рубль, доллар; курсы задаёт пользователь вручную
- кошельки, карты и долги заводятся самим пользователем — дефолтных банков нет
- свои категории доходов и расходов поверх базового набора
- лимиты по категориям с прогресс-баром и подсветкой перерасхода
- сравнение с прошлым месяцем на главной и в аналитике
- вкладка долгов: срок погашения, напоминание за N дней, ежемесячные платежи
- разбор бюджета моделью через OpenRouter (в том числе бесплатными)
- светлая и тёмная тема
- редактирование и удаление любой операции
- PWA: ставится на домашний экран, статика работает офлайн

## Стек

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · dnd-kit ·
Supabase (Postgres + Auth, RLS) · Vercel.

## Запуск

```bash
npm install
cp .env.example .env.local   # вписать ключи
npm run dev
```

### 1. Supabase

1. Создать проект на [supabase.com](https://supabase.com).
2. Выполнить `supabase/migrations/0001_init.sql` в SQL Editor — он создаёт
   таблицы, представления, политики RLS и триггер, который при регистрации
   заводит профиль, курсы валют и стартовый набор категорий.
3. Project Settings → API: скопировать `Project URL` и `anon public` ключ в
   `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. Authentication → URL Configuration: в `Redirect URLs` добавить
   `https://<домен>/auth/callback`.

Все таблицы закрыты Row Level Security: строка видна только своему владельцу
(`auth.uid()`). Диск базы у Supabase шифруется, соединение идёт по TLS.

### 2. OpenRouter

Ключ с [openrouter.ai](https://openrouter.ai) кладётся в `OPENROUTER_API_KEY`.
Он читается только в серверном роуте `/api/analyze` и в браузер не попадает.
`AI_DAILY_LIMIT` ограничивает число разборов в сутки на пользователя, чтобы
один аккаунт не выжег общий ключ. Модель выбирается в настройках приложения —
список в `src/lib/aiModels.ts`, поле редактируемое, так что идентификатор можно
поменять без передеплоя.

В модель уходят только агрегаты: суммы по категориям, балансы кошельков и
параметры долгов. Комментарии к операциям не отправляются.

### 3. Vercel

Импортировать репозиторий, добавить те же переменные окружения (включая
`NEXT_PUBLIC_SITE_URL` — OpenRouter просит его в заголовке `HTTP-Referer`),
задеплоить.

## Модель данных

| Таблица | Назначение |
|---|---|
| `profiles` | базовая валюта, тема, выбранная модель |
| `exchange_rates` | курсы к базовой валюте, правятся вручную |
| `wallets` | наличные, карты и долги; у долгов — срок, напоминание, платёж |
| `categories` | категории доходов и расходов, лимит на месяц |
| `transactions` | все операции одной таблицей |
| `ai_usage` | счётчик обращений к модели за сутки |

Типы операций: `income` (доход в категорию), `allocation` (часть дохода
перенесена в кошелёк), `expense`, `transfer`, `adjustment` (ручная правка
баланса). Балансы нигде не хранятся — их считает представление
`wallet_balances`, нераспределённый доход — `income_pools`. Поэтому правка или
удаление любой операции сразу и корректно меняет все итоги.

Удаление кошелька или категории — это архивация: история операций остаётся.

При регистрации создаётся только профиль и три курса валют. Категорий,
кошельков и банков по умолчанию нет — пользователь собирает свою панель сам.
На главной долги свёрнуты в два кружка «Долги −» и «Долги +»; конкретные
обязательства со сроками и платежами живут на вкладке «Долги».

## Разделы

- **Панель** — три блока иконок, месяц переключается в шапке
- **История** — операции месяца, поиск по примечаниям, сальдо, правка и удаление
- **Отчет** — доходы / расходы / итого, разбивка по категориям со сравнением с прошлым месяцем и лимитами, разбор бюджета моделью
- **Долги** — я должен / мне должны / ежемесячные, с внесением платежа и возвратом
- **Настройки** — валюта, курсы, тема, модель, выход
