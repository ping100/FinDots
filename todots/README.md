# ToDots — задачи и напоминания

Второе приложение экосистемы Findots: тот же знак, та же тема, тот же
принцип «пустой старт» — ни одной категории по умолчанию, всё заводится
через «+».

## Концепция

- **Лента дат сверху** — кружки-дни (тот же язык, что переключатель месяца
  в Findots). Сегодняшний день обведён, выбранный — залит акцентом. Под
  днём с незавершёнными задачами — точка.
- **Список задач выбранного дня** — сначала без времени, потом по времени
  по возрастанию. Выполненные и задачи без даты («Когда-нибудь») свёрнуты
  отдельными секциями.
- **Карточка задачи** — кружок-чекбокс окрашен по приоритету (серый/жёлтый/
  красный), время — опциональное поле, которое одновременно сортирует
  карточку и задаёт момент напоминания (отдельного поля «напомнить» нет),
  категория — цветная плашка справа, как категории расходов в Findots.
- **Перенос между днями** — задачу можно перетащить на другой кружок в
  ленте дат, тот же жест, что перенос кошелька в Findots.

Сознательно вне рамок первой версии: повторяющиеся задачи/привычки,
геймификация, тайм-блоки по часам, подтверждение почты, вход через Google,
push-уведомления (время у задачи есть, а доставка напоминания — отдельная
задача на потом), сгенерированные PWA-иконки и service worker.

## Стек

Next.js (App Router, TypeScript) · Tailwind CSS 4 · @dnd-kit/core ·
Supabase (Postgres + Auth, RLS).

Токены темы, шрифт (Onest), анимации знака и переходов, `PALETTE` и `Icon` —
общие по духу с Findots (и местами скопированы буквально): это должно
ощущаться как одна экосистема, а не как два приложения, которые просто
похоже покрашены.

## Запуск

```bash
cd todots
npm install
cp .env.example .env.local   # вписать ключи Supabase
npm run dev
```

### Supabase

Можно завести отдельный проект Supabase, а можно применить миграцию из
`supabase/migrations/` к тому же проекту, что уже обслуживает Findots —
таблицы называются `task_categories` и `tasks`, с `categories` и
`transactions` Findots они не пересекаются. Второй путь удобен, если в
будущем экосистема объединит вход: тогда `auth.users` уже общий, а
привязка задач к пользователю (`auth.uid()`) заработает сама.

## Модель данных

| Таблица | Назначение |
|---|---|
| `profiles` | тема |
| `task_categories` | категории задач: название, иконка, цвет |
| `tasks` | задачи: заголовок, дата (может быть пустой), время (может быть пустым), категория, приоритет, отметка о выполнении |

Категория при удалении архивируется, а не стирается — так задачи в истории
не теряют название.
